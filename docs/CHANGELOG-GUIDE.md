# 更新日志书写规范

`docs/CHANGELOG.md` 面向最终用户，遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 格式与[语义化版本](https://semver.org/lang/zh-CN/)规范。发版 CI 通过 `scripts/changelog-section.py` 自动截取对应版本小节作为 GitHub Release 说明（见 [RELEASE.md](RELEASE.md)），同时可用于服务端应用内更新提示。内部实现细节保留在提交记录与技术文档中，不写入更新日志。

## 结构规范

```markdown
## [Unreleased]

## [1.1.0] - 2026-11-22

### 变更

- 精简应用资源与调试日志，安装包体积由 1.66 MB 缩减至 1.41 MB。

### 修复

- 修复开启推送后切换深浅色模式时，后台残留重复消息连接并持续耗电的问题。

[Unreleased]: https://github.com/liminalselves/liminalselves_app/compare/v1.1.0...HEAD
[1.1.0]: https://github.com/liminalselves/liminalselves_app/compare/v1.0.0...v1.1.0
[1.0.0]: https://github.com/liminalselves/liminalselves_app/releases/tag/v1.0.0
```

1. **Unreleased 小节**：文件顶部常驻 `## [Unreleased]`。日常开发将用户可感知的改动记录于此；发布前将其整理归入新版本小节，并保留空的 `## [Unreleased]`。
2. **版本标题**：严格使用 `## [x.y.z] - YYYY-MM-DD`（不带 `v` 前缀，日期为实际发布日）。CI 依赖该标题匹配正文，格式错误或正文为空会导致发版失败。
3. **标准分组**：按 Keep a Changelog 顺序使用以下六个分组，无对应内容的分组省略：`### 新增`、`### 变更`、`### 弃用`、`### 移除`、`### 修复`、`### 安全`。
4. **初始及无分组版本**：首个正式版本或无需细分子分组的版本，可直接填写简短版本说明（例如「首个正式版本。」），确保小节正文非空即可。
5. **列表条目**：以 `- ` 开头，每条陈述一项独立改动，单句成条，句末使用中文句号。
6. **链接引用**：文末按版本维护 compare 与 tag 引用链接；每次发版后更新 `[Unreleased]` 的对比起点并追加新版本链接。

## 行文要求

1. **只写用户可感知的变化**：说明改动所处的场景与实际结果。依赖版本调整、纯代码重构、文档修订、CI 配置修改等对用户无感知的事项不写入更新日志。
2. **客观、正式、简洁**：使用平实的陈述句直接表述结果（例如「新增……」「优化……」「修复……的问题」），避免仅描述故障现象而造成歧义；不使用第一、二人称说教，不使用「全新」「大幅」「极致」「显著」等宣传性词汇；具备实测对比数据时直接注明具体数值。
3. **禁止空泛表达**：不得出现「修复若干已知问题」「优化部分体验」「提升稳定性」等无实际信息的表述；多项零碎调整需合并时，应写明具体受影响的界面或功能范围。
4. **禁用要素**：
   - 文件路径、类名、方法名、接口名、配置键名及命令行。
   - 内部工程术语与英文缩写（如 WebView、SDK、API、R8、DEX 等）；Android、iOS、Misskey、Wi-Fi 等通用产品或技术名词除外。
   - 提交前缀、PR 编号及作者名称。
   - 反引号、超链接、图片、表格、多级嵌套列表及表情符号。

### 正反对照

| 不规范写法 | 规范写法 |
| --- | --- |
| 修复 WebView textZoom 跟随系统字号 | 修复系统字体调大后应用内文字额外放大、图标偏离中心的问题。 |
| 重构 NativeWsManager 重连逻辑 | 优化后台消息断线重连机制，网络恢复后更快接收新通知。 |
| 升级 AGP 到 9.4.1 / 整理 docs 目录 | 不写入更新日志（对用户无感知）。 |
| 修复若干已知问题 | 写出具体场景，如「修复部分页面返回时导航记录丢失的问题。」 |

## 发布前核对

- [ ] `## [Unreleased]` 中的条目已归入 `## [x.y.z] - YYYY-MM-DD` 小节，且 `## [Unreleased]` 已置空。
- [ ] 版本标题、Git 标签与 `pubspec.yaml` 版本号保持一致。
- [ ] 分组仅使用 Keep a Changelog 六个标准类别（首个正式版本等简短说明版本除外）。
- [ ] 全部条目客观、简洁、单句成条、句号结尾，且无术语缩写、路径、接口名与禁用格式。
- [ ] 文末 compare / tag 引用链接已更新，本地执行 `python3 scripts/changelog-section.py <版本>` 可正常输出。
